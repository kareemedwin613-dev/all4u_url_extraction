# v0.7 testing

## Automated commands

    npm run lint
    npm run typecheck
    npm test
    npm run test:db
    npm run build:dashboard
    npm run build:extension
    npm run check

Database tests require Docker and a running local Supabase stack. Start that stack with `npx supabase start`, then run `npm run test:db`. The pgTAP tests cover preview purity and limits, inactive/category/missing exclusions, duplicates, partial creation, idempotency, bulk assignment, active-Applier validation, assignment history, role denial, sorted RPCs, RLS, and individual v0.6 regression.

## Manual acceptance checklist

- Applying Manager and Admin see JD checkboxes and Application Batches navigation.
- Applier-only, Developer-only, and Development Manager-only users do not see bulk controls and receive Access Denied for direct bulk URLs.
- Selection persists while changing JD result pages.
- Preview initially selects every eligible non-duplicate pair.
- Search and all seven filters work without clearing selection on other pages.
- Duplicate and invalid rows are labelled and disabled.
- Confirmation counts match the selected pairs and show the unassigned defaults.
- A mixed-validity submission completes with warnings and retains every outcome.
- Repeating the same pairs produces duplicate outcomes without extra Applications.
- Created Applications have no assignee, no assigner, `UNASSIGNED`, `NOT_APPLIED`, and `NORMAL`.
- Batch list/detail pages show counts, creator, status, timestamps, and per-row results.
- Application list filters correctly between bulk, individual, and a selected batch.
- Existing individual creation, assignment, Applier progress, private Resume opening, JD capture, and Resume upload still work.
- Applying Manager and Admin can select Applications across pages and assign them to one active Applier in one action.
- Bulk unassignment is an explicit choice; the confirmation button remains disabled until an action is selected.
- Repeating an unchanged assignment reports it as unchanged and does not add duplicate history.
- Every dashboard data-table column shows usable ascending/descending sorting; paginated views retain the chosen order while paging.

Do not record a live migration, browser test, or manual checklist item as passed unless it was actually performed in that environment.
