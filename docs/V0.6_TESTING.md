# v0.6 testing

## Automated checks

    npm run lint
    npm run typecheck
    npm test
    npm run test:db
    npm run build:dashboard
    npm run build:extension
    npm run check

Database tests require a local Supabase stack. They cover RLS, manager/Admin creation, duplicate protection, active-Applier validation, assigned-only reads, protected progress fields, atomic histories, no-op behavior, reassignment, unassignment, deletion denial, counts, and private Resume authorization.

## Manual acceptance checklist

Do not mark an item passed without testing it against a migrated project:

1. Manager creates an assigned and an unassigned Application.
2. Duplicate JD/Resume pairing shows a friendly error.
3. Assigned Applier sees only their Application and opens its Resume through a short-lived link.
4. Applier updates both status models and APPLIED fills the applied time.
5. Manager reassigns and unassigns; both histories show the actor and reason.
6. Developer-only navigation has no Applications entry and direct route access is denied.
7. Admin user management, job/resume pages, extension extraction/capture, upload, login, and logout still work.
8. As Admin, upload a text-based PDF, review the extracted fields, save it, and confirm the Resume detail and private original file open correctly.
9. Confirm an Applier or Applying Manager cannot open the dashboard Upload Resume route.
10. On Job Descriptions, apply category, seniority, status, and company/title search filters individually and together; confirm the URL and result rows reflect every selection. Clear filters and confirm the controls visibly reset.
11. As an Admin, select a Resume PDF containing at least two employers. Confirm Professional Experience shows separate cards with company, title, dates, location, and one multiline achievements-and-responsibilities field. Correct a field, add and remove an experience, then save the reviewed version.
12. Open the saved Resume detail and confirm the structured positions are displayed separately while the original extracted text and private source PDF remain available.
13. Sign in as an active Applier assigned to an Application. Change Work Status, Application Status, and Application URL, then save. Confirm the update succeeds and priority, due date, applied timestamp, and manager notes remain unchanged.
14. Confirm an Applier cannot see manager-only progress inputs and cannot cancel, reassign, or update an Application assigned to another user.
