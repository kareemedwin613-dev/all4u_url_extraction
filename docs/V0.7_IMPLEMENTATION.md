# v0.7 implementation record

## Pre-change architecture inspected

- Repository: one npm workspace with `extension/`, `dashboard/`, `supabase/`, shared test fixtures, build scripts, and documentation.
- Extension: Manifest V3 side panel built from plain JavaScript modules; content extraction runs in the page, while Supabase Auth/data access runs in the side panel. Host access and the existing v0.3 extraction rules are unchanged.
- Dashboard: React 19 and Vite with a hash router in `dashboard/src/router.js`; route/capability decisions live under `dashboard/src/access/`; pages use local React state and Supabase service modules.
- Design system: Ant Design provider/theme in `dashboard/src/main.jsx` and `dashboard/src/theme.js`, with shared loading/error/table/tag/page-heading components in `dashboard/src/components/ui.jsx`.
- Data: ordered SQL migrations define categories, JDs, private structured Resumes, profiles, five fixed roles, multi-role assignments, and the v0.6 `applications`, assignment-history, and status-history tables.
- Security: business tables and private Storage use RLS. Application mutation functions follow authenticated `SECURITY DEFINER` RPC conventions, set a controlled search path, call role helpers, derive the actor from `auth.uid()`, and revoke direct mutation.
- Commands: npm scripts provide Node frontend/integration/regression tests, pgTAP database tests, lint, JavaScript module-contract checking, dashboard production build, extension production build, and aggregate validation.

## v0.7 additions

- Migration: `202607240016_v0_7_bulk_application_creation.sql`.
- Tables: `application_creation_batches` and `application_creation_batch_results`.
- Application column: nullable `creation_batch_id`; existing individual rows remain null.
- Protected RPCs: `preview_bulk_applications`, `create_applications_bulk`, `list_application_batches`, `list_application_batch_options`, `get_application_batch_detail`, and `list_applications_v07`.
- Dashboard routes: `/applications/bulk-create`, `/application-batches`, and `/application-batches/:id`.
- UI: role-gated JD selection, preview summary/filter/table/confirmation/result screens, batch list/detail, and Application batch/creation-mode filters.

The bulk functions use set-based joins and insertion. The browser sends one preview request and one creation request; it does not issue per-JD, per-Resume, or per-Application calls. Resume Storage policies were not broadened.
