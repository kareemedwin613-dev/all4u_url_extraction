# v0.5 testing

## Automated commands

```sh
npm test
npm run test:db
npm run build:dashboard
npm run build:extension
npm run check
```

`npm test` runs dashboard access/capability/route/Admin-service tests, extension access tests, and every v0.3/v0.4 regression test. `npm run test:db` requires a running local Supabase stack and Docker; it runs pgTAP schema, RLS, RPC, profile, role, last-Admin, and Storage tests. `npm run check` runs JavaScript tests, both production builds, and isolated-bundle validation.

## Test accounts

Use non-production identities:

| Account | Role/status |
|---|---|
| `admin@example.test` | ADMIN |
| `applier@example.test` | APPLIER |
| `manager@example.test` | APPLYING_MANAGER |
| `developer@example.test` | DEVELOPER |
| `devmanager@example.test` | DEVELOPMENT_MANAGER |
| `multi@example.test` | APPLIER + DEVELOPER |
| `pending@example.test` | no roles |
| `inactive@example.test` | APPLIER + INACTIVE |

Expected navigation:

- Applier/Applying Manager: Overview, Job Descriptions, Resumes, My Profile.
- Developer/Development Manager: Overview, My Profile.
- Admin: Overview, Job Descriptions, Resumes, Users, Roles, My Profile.
- Multiple roles: deduplicated union.
- Pending/inactive: dedicated state and Sign Out only.

## Manual acceptance checklist

- Applying Manager/Admin: extract a supported JD, review fields, save, and confirm it appears in dashboard.
- New user: verify profile creation and Pending Access before assignment.
- Admin: search/filter/paginate Users; assign/remove multiple roles; activate/deactivate a user.
- Applier: read shared JDs/resumes and open a source resume; verify extension writes are unavailable.
- Developer: verify direct job, resume, and Admin hashes show Access Denied and direct Supabase reads return no rows.
- Multi-role user: verify business navigation is granted by Applier while Admin remains unavailable.
- Inactive user: verify dashboard and extension show Account Inactive and database reads are denied.
- Reactivated user: verify existing roles remain and access returns after refresh/sign-in.
- Sign out: refresh a protected hash and confirm login appears without stale data.

## Last active Admin test

With exactly one active Admin, try removing ADMIN and then setting that user INACTIVE. Both must return “At least one active Admin must remain.” Add a second active Admin and repeat against the first; the change may then succeed. Do not perform this on a production workspace without a recovery plan.

## Storage test

Upload a small test resume as Applying Manager. Confirm Applier receives a short-lived signed URL. Confirm Developer, pending, and inactive accounts cannot select the object or generate a signed URL. Confirm Applying Manager cannot upload to another user UUID folder and that both buckets remain private.

## JD extraction regression

As Applying Manager/Admin, test Paylocity, iCIMS, and Greenhouse-style fixtures or supported live pages. Confirm company, title, source URL, full description, location, work arrangement, salary, industry, security/travel flags, and detected skills still populate. Extraction selectors and payload construction were not redesigned for v0.5.
