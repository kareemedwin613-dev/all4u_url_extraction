# v0.7 setup

## Prerequisites

- The v0.6 schema, profiles, roles, and Application workflow are already installed.
- The dashboard uses a Supabase project URL plus publishable/anon key only.
- Applying Manager and Admin users are active and have the corresponding fixed role.

## Apply the migration

From the repository root, link the intended Supabase project if needed, inspect the pending SQL, and then deploy it explicitly:

    npx supabase link --project-ref YOUR_PROJECT_REF
    npx supabase db push --dry-run --linked
    npx supabase db push --linked

The v0.7 file is `supabase/migrations/202607240016_v0_7_bulk_application_creation.sql`. It creates the batch audit tables, adds nullable `applications.creation_batch_id`, enables RLS, and installs the protected preview/create/list functions. Apply `supabase/migrations/202607240017_bulk_assignment_and_table_sorting.sql` afterward to install protected bulk assignment and sortable paginated-list RPCs.

Do not copy a service-role key, secret key, or database password into `.env`, dashboard code, or extension settings.

## Assign existing Applications in bulk

1. Sign in as an active Applying Manager or Admin and open **Applications**.
2. Select up to 500 rows. Selection persists while moving between result pages.
3. Choose **Assign Selected**.
4. Select one active Applier, or explicitly choose **Unassign selected Applications**.
5. Optionally enter an audit reason and confirm.

The operation is one set-based RPC call. It reports changed, unchanged, and missing rows, and records history only where the assignee actually changed.

## Run locally

    npm install
    npm run dev:dashboard

Reload the unpacked extension after `npm run build:extension` only if Chrome needs the version update; v0.7 does not change extraction or Storage behavior.

## Use the workflow

1. Sign in as an active Applying Manager or Admin.
2. Open Job Descriptions and select up to 100 rows, including selections on different result pages.
3. Choose **Create Applications** and review the server-generated combinations.
4. Filter or adjust the selected eligible pairs, then confirm once.
5. Review the result or open **Application Batches** for the durable audit record.

If the browser reports a network interruption after submission, check Application Batches before retrying. The server prevents duplicate JD–Resume Applications, but checking first avoids an unnecessary duplicate-only batch.
