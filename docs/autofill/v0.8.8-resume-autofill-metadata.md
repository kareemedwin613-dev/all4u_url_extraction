# v0.8.8 Resume Autofill Metadata

The Resume is the canonical record for candidate and autofill information. v0.8.8 intentionally creates no `candidates`, `candidate_profiles`, `candidate_links`, or other Candidate child tables.

Personal details, address, links, and review metadata are columns on `resumes`. Repeatable employment, education, and certification information remains in the existing versioned `structured_content` JSON document. Version 3 changes education to an ordered array while preserving older free-text education in `education_legacy_text`; it does not parse that text again or pretend that it is structured truth.

The roadmap-compatible endpoints remain under `/api/v1/candidates/:resumeId`, where `:resumeId` is the Resume ID. Applying Managers and Admins can review and edit metadata. An active Applier can read it only when an Application using that Resume is assigned to them. The request-scoped Supabase client and PostgreSQL authorization functions enforce those rules.

Any update to employment or education returns the Resume to `NEEDS_REVIEW`. A Manager or Admin must explicitly verify it again. Autofill eligibility requires an active Resume, an HTTP(S) job URL, and `resumes.profile_review_status = 'VERIFIED'`.

This milestone stores reviewed data but does not fill or submit job-site forms.
