# v0.8.8 Structured Candidate Profile

v0.8.8 stores one reviewable Candidate Profile for each Resume. It intentionally does not introduce a separate `candidates` identity table or merge multiple Resumes into one person record.

Existing and newly uploaded Resumes seed `candidate_profiles` with `NEEDS_REVIEW`. Extracted values are never considered verified automatically. An Applying Manager or Admin can review personal/contact details, primary address, links, employment history, and education from the Resume detail page. Marking the profile verified records the reviewer and time; changing it back clears that attestation.

The API exposes the roadmap endpoints under `/api/v1/candidates/:profileId`. Here, `:profileId` is the Resume-scoped `candidate_profiles.id`, not a separate candidate account. Applying Managers and Admins may edit. An active Applier may read a profile only when an Application using that Resume is assigned to them. Database RLS and RPC authorization enforce the same rule independently of the dashboard.

Future autofill is advertised as available only when the Application Resume is active, the job URL is HTTP(S), and the attached profile is `VERIFIED`. This milestone does not fill job-site fields or submit Applications.
