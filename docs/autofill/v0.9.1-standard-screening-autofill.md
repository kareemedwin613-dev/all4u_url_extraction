# v0.9.1 Standard Screening Autofill

The extension now detects and fills standard screening controls from active, verified Resume-owned answers returned for the exact authorized Application Autofill session.

## Flow

`Detect -> Fill supported fields -> Verify -> Human submit`

- Page inspection receives answer keys, types, and approved question patterns, but not answer values.
- Answer values are loaded from the backend immediately before filling.
- All supported detected fields are filled automatically; failed or unsupported fields remain manual.
- Desired salary uses the configured fallback or JD midpoint automatically.
- When the JD contains a complete numeric salary range, the preview uses its midpoint. Otherwise it falls back to the active, verified desired-salary answer saved on the Resume.
- Failed screening values remain editable for a retry.
- Every attempted result is verified after browser input/change events.
- The extension never submits an application.
- Native selects, radio groups, and React-based ATS comboboxes such as current Greenhouse forms are supported.
- Current location is derived from the verified Resume address. Current company is derived from the employment entry explicitly marked current.
- Gender, race/ethnicity, and veteran-status answers are optional Resume-owned values and are filled automatically only when an active saved answer exactly matches a supported question.

## Supported controls

- Boolean answers on yes/no radio groups and selects
- Single-select work preference on radio groups and selects
- ISO dates on date or short-text inputs
- Numeric experience on number or short-text inputs
- Candidate-approved short text on single-line inputs

Textareas, checkboxes, long-form prompts, cover letters, essays, attestations, legal interpretation, and automatic salary negotiation are excluded.

## Manual Answer Library setup

Managers configure all supported answers in one fixed form on the Resume page. Blank rows are ignored, so a manager can save the useful answers in one action without creating records individually. The API sends the configured rows to one protected bulk-save RPC; the transaction either saves the complete request or rolls it back.

## Safety

Disability, medical, religion, sexual-orientation, criminal-history, accommodation, security-clearance, Public Trust, export-control, background-check, drug-screening, restrictive-covenant, and attestation questions remain blocked. Gender, race/ethnicity, and veteran status are the only voluntary self-identification categories supported, and only from explicitly configured Answer Library keys.
