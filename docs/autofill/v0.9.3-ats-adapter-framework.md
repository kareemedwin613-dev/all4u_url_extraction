# v0.9.3 ATS adapter framework

Autofill and Resume attachment now run through a small adapter registry instead of embedding every site behavior in the content-script message handler.

Selection order is:

1. Exact-domain adapters registered by the application
2. ATS-family adapters
3. Generic HTML fallback
4. Existing manual fallback when the selected adapter cannot safely handle a control

The first ATS-family adapters are Greenhouse and Workable because both appear in the project's tested application workflow. They currently reuse the hardened generic field algorithms while providing an isolated location for future site-specific selectors and interaction behavior.

Every adapter exposes detection, Resume-field detection, Resume attachment, field filling, and verification capabilities. The side panel displays the selected adapter and version. A fill is rejected if navigation changes the selected adapter after detection.

Adapters receive only the in-memory authorized Autofill context supplied by the content-script caller. They do not fetch the backend or Supabase, persist profile values, access extension storage, or submit forms. v0.9.3 requires no database migration.
