# v0.9.4 Autofill session feedback

v0.9.4 extends `application_extension_sessions`; it does not introduce a second Autofill-session model.

## Recorded data

Each Autofill run can record the Resume ID and `updated_at` snapshot, selected ATS adapter and version, normalized target hostname, aggregate detected/selected/succeeded/failed/unresolved counts, and bounded field outcomes in `application_extension_session_fields`.

Field outcomes contain only a normalized `candidate.*` or `screening.*` key, a zero-based occurrence index, confidence, outcome, adapter metadata, and an optional allowlisted-style error code. Repeated writes for the same session, normalized key, and occurrence update that outcome, which supports retries without creating duplicate audit rows.

## Privacy and authorization

- The extension never sends field values, labels, unresolved question text, Resume text, signed URLs, or tokens in telemetry.
- The API DTO rejects unknown properties before the database call.
- `record_application_autofill_telemetry_v094` verifies an active authenticated user, owned Autofill session, Application visibility, session lifetime, and the exact Resume snapshot.
- Direct inserts, updates, and deletes on the field table are denied to authenticated clients. Writes use the protected RPC through a request-scoped user Supabase client, so RLS and database authorization remain active.
- RLS allows a user to read only their own session fields while they can still view the associated Application.

## Applying the migration

Run `supabase db push` from the repository root after linking the intended Supabase project. The migration is `202608020032_v0_9_4_autofill_session_feedback.sql`.

No live migration is performed automatically by the application build.
