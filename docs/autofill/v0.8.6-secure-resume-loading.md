# v0.8.6 Secure Resume loading

## Flow

1. An authorized user starts **Load Resume** from an eligible Application.
2. The v0.8.5 handoff opens or focuses the Application job URL and creates a short-lived extension session.
3. The signed-in side panel sends the session ID, Application ID, backend URL, and current access token directly to the extension service worker. The token is not stored.
4. `POST /api/v1/applications/:id/resume-access` verifies the active user and Application visibility through the existing database-backed role checks and Application-to-Resume lookup.
5. The API checks that the exact Application Resume is active and has valid filename, MIME type, and size metadata.
6. A request-scoped Supabase client creates a 60-second signed URL. Existing private Storage RLS remains active.
7. The service worker downloads the file immediately, validates its declared and actual size, and retains only the bytes and safe metadata in an in-memory map.
8. Expired access receives one fresh access request. Reset, cancellation, expiry, or service-worker termination clears the in-memory Resume.

## Security properties

- Supported files are PDF, DOCX, or text and are limited to 5 MiB.
- Resume bytes are never written to `chrome.storage.local`, `chrome.storage.session`, IndexedDB, or Cache Storage.
- Signed URLs and access tokens are not stored or logged.
- Only the extension side panel can initiate a Resume load; dashboard content scripts and job pages cannot request it.
- The API uses the authenticated user's Supabase client. No service-role client is used.
- The existing `get_application_resume_file` RPC verifies that the Resume belongs to the requested Application and that the actor may view that Application.
- Private `original-resumes` Storage RLS limits Managers/Admins and the assigned active Applier.

## Database impact

No migration is required. v0.8.6 reuses the existing Application Resume RPC, Resume metadata, private Storage bucket, and Storage RLS policies.

## Deferred to v0.8.7

The memory store can create a browser `File` when a supported upload input needs it. Detection and attachment to job-site file inputs are intentionally deferred to v0.8.7.
