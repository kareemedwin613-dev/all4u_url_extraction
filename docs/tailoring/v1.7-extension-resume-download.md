# v1.7 extension Resume delivery

v1.7 makes the Resume attached to an Application explicit in the Applier extension. Each card shows the immutable Resume number and whether the attached variant is Original or Tailored. **Download Resume** replaces the ambiguous **Load Resume** action.

The extension calls NestJS for the selected Application. PostgreSQL verifies that the caller can view that Application and resolves only its active attached Resume. NestJS creates a 90-second signed URL through the request-scoped user client, and Chrome's download manager starts a user-visible, uniquely named download. The extension never queries a Resume table or private Storage directly.

The Application list uses one set-based RPC and includes the attached Resume identity in the same response. It does not perform one request per card. Autofill remains a separate action and continues using the existing verified metadata and session controls.

## Explicit boundary

v1.7 does not render a new file, change the Application's Resume, expose tailored children in the general Resume dashboard, submit an application, or broaden Storage policies. DOCX remains the tailored artifact format produced by v1.6.

## Attach Resume (in-page delivery)

**Attach Resume** on each Application card puts the attached Resume (Original or Tailored) straight into the job site's Resume file input, so Appliers no longer download and re-upload it. **Autofill** does the same as its first step, before field detection, because ATS resume parsers repopulate fields on upload. **Download Resume** remains the manual fallback.

- The side panel resolves the file through the same `get_application_resume_download_v17` path as Download Resume, so the uploaded filename is the candidate-facing `<Candidate> Resume - App <N>` name. The service worker receives only the short-lived signed URL and metadata, never the API token; if the URL expires before the fetch, the panel requests one fresh URL.
- Bytes stay in service-worker memory and are cleared with the session. The v0.8.7 detector, `accept` validation, `DataTransfer` assignment, and verification are unchanged; the extension never submits the form.
- Panel-started sessions act on the current tab (the application form the Applier is looking at). Attachment waits for the tab to finish loading and refuses a tab that navigated to another origin.
- A Resume problem never blocks field Autofill; it appears in the session banner with **Retry Attachment**. Resumes whose Autofill preferences require review, and recovered Autofill sessions, load the Resume but wait for **Attach Resume to Page** instead of uploading again.
