# v1.8 versioned DOCX templates

v1.8 adds three fixed rendering layouts for an approved Application Resume:

- `CLASSIC_V1`: traditional centered header and blue section rules;
- `MODERN_V1`: left-aligned navy header and teal section accents; and
- `COMPACT_V1`: reduced spacing for longer professional histories.

Applying Managers and Admins select a template after content approval and before materialization. Selection uses optimistic concurrency and is rejected after rendering begins. The selected versioned key, selecting user, and selection time are retained on the tailoring job. The final `TAILORED` Resume also stores the template key, so its layout remains auditable even when later template versions are introduced.

The template catalog is code-owned and returned by NestJS. Users cannot upload templates, HTML, CSS, macros, scripts, or arbitrary rendering configuration. The existing v1.6 begin/finalize RPC names remain stable; private wrappers add the selected key while preserving atomic Resume creation and Application switching.

## Explicit boundary

v1.8 still creates DOCX only. It does not render PDF, edit an already-materialized file, change source Resume metadata, expose tailored children in the primary Resume list, run Codex during rendering, or submit a job application.
