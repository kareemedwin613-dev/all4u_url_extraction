# v1.5 one-command local tailoring runner

v1.5 removes the need to inspect browser storage, copy a Supabase access token, identify the job UUID, or choose an artifact path. An Applying Manager or Admin creates a runner command from the tailoring review page and runs it once from the repository root.

The ticket contains 256 bits of randomness, is stored only as a SHA-256 hash, expires after ten minutes if unclaimed, and is scoped to one tailoring job. Claiming it creates a thirty-minute run window. A newly issued ticket revokes any earlier active ticket for the job. Completion makes the ticket unusable.

The capability endpoints can only return the v1.2 sanitized tailoring contract, accept one schema-validated preview, or record one allowlisted failure code. They cannot list jobs, read contact details, download a Resume, access Storage, approve content, create a Resume row, or change an Application. The ticket table has RLS enabled and no direct browser table privileges.

## Operator workflow

1. Request tailoring from an Application detail page.
2. On the tailoring page, select **Create Runner Command**.
3. Copy and run the displayed command from the repository root.
4. Keep the dashboard page open; it polls every four seconds.
5. Review, edit, and approve or reject the resulting structured preview.

The worker still requires a locally installed and authenticated Codex CLI. The ticket replaces application authentication only; it is not an AI API credential.

## Explicit boundary

v1.5 does not render DOCX/PDF, create a `TAILORED` Resume row, write private Storage, change `applications.resume_id`, or change the Chrome extension.
