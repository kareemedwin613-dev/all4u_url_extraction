# v1.3 Application tailoring preview lifecycle

v1.3 connects the isolated v1.2 Codex proof to an authenticated, Application-scoped lifecycle. Applying Managers and Admins can request one idempotent tailoring job for an Application, retrieve a deliberately sanitized input contract, and persist a schema-validated preview for human review.

The database derives the JD and Resume from the Application. It rejects inactive or tailored source Resumes, incomplete structured employment, changed Application pairs, invented skills, missing experience records, unsafe status transitions, and preview submission by a different processor.

The NestJS API continues to use the caller's verified Supabase JWT and request-scoped client, so PostgreSQL RLS and the protected RPCs remain authoritative. The local worker keeps the access token outside the Codex subprocess and sends Codex only the v1.2 sanitized input contract.

## Explicit boundary

This milestone stores a reviewable JSON preview only. It does not:

- create a `TAILORED` Resume row;
- create DOCX or PDF bytes;
- write to the `tailored-resumes` bucket;
- change `applications.resume_id`;
- approve or reject a preview;
- change the Chrome extension.

Those operations remain later, separately reviewable milestones.
