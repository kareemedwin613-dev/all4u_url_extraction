# v1.9 PDF materialization

v1.9 lets an Applying Manager or Admin choose `DOCX` or `PDF` after the tailored content is approved and before materialization begins. Both formats use the same human-approved summary, source-linked experience content, skills, and fixed v1.8 template. Rendering happens inside NestJS; no browser, external conversion service, OpenAI API, or other AI API receives Resume data.

## Data and audit model

`tailoring_jobs.render_format` is constrained to `DOCX` or `PDF`. `format_selected_by` and `format_selected_at` retain the selection audit. The final `TAILORED` child stores the same `render_format`; `ORIGINAL` Resumes keep this field null. Existing tailored DOCX artifacts are backfilled as `DOCX`.

The protected `select_tailoring_format_v19` RPC permits only active Applying Managers and Admins, only while a job is `APPROVED`, and uses `updated_at` for optimistic concurrency. The selected format is immutable once rendering begins.

## Materialization and Storage

`begin_tailoring_materialization_v19` reserves the existing job and returns an exact job-specific `.docx` or `.pdf` path. The API renders bounded bytes in memory, hashes them, and uploads once with the authenticated caller's Supabase client. `finalize_tailoring_materialization_v19` locks and revalidates the job, Application, original Resume, selected format, MIME type, path, filename, file size, checksum, private Storage object, and approved preview before it atomically:

1. creates one numbered `TAILORED` child;
2. records its template and format;
3. completes the tailoring job; and
4. switches only that Application to the child Resume.

The Storage insert policy accepts only the exact expected object for the active manager-owned materialization. Failure cleanup and retry behavior remain unchanged. A completed request remains idempotent.

Authenticated execution of the legacy v1.6 begin/finalize RPCs is revoked. Those functions remain internal compatibility helpers called only by the protected v1.9 flow, preventing a caller from bypassing the selected-format audit.

## Boundary

v1.9 does not convert an arbitrary uploaded document, mutate the original Resume, expose tailored children in the primary Resume dashboard, run Codex during rendering, submit an application, or add user-authored templates. PDF uses built-in server-side fonts and fixed code-owned layout rules.
